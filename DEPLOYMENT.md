# Deployment Guide — Iron Oath on Neon + Render

This guide covers the intended production path: Neon Lakebase PostgreSQL for data, Render for the Flask/Gunicorn web service, HTTPS, migrations and PWA verification.

## 1. Neon database

The repository's Neon CLI context points at:

- Project: `gym-logbook` (`summer-firefly-71446207`)
- Development branch: `gym-app-dev` (`br-purple-glitter-zaacqolw`)
- Production branch: `main` (`br-rough-sea-za0q92w2`)

Use `gym-app-dev` for development/staging. Leave `main` untouched until you are ready to promote the schema, then test the migration on a branch of `main` before applying it there.

Neon gives two connection strings:

| Variable | Hostname | Used for |
| --- | --- | --- |
| `DATABASE_URL` | contains `-pooler` | Flask application traffic |
| `DATABASE_URL_UNPOOLED` | no `-pooler` | Alembic/Flask-Migrate, dumps, admin tasks |

`migrations/env.py` prefers `DATABASE_URL_UNPOOLED` and converts `postgres://`/`postgresql://` to the psycopg 3 driver automatically. Never run migrations through the pooled URL.

Pull a branch's environment locally with:

```bash
neon link --project-id summer-firefly-71446207 --branch gym-app-dev -y --no-env-pull
neon env pull --file .env
```

`.env` is ignored by Git.

## 2. Render environment variables

Create a Web Service from this repository (or deploy the included `render.yaml` Blueprint) and set:

| Variable | Value | Notes |
| --- | --- | --- |
| `DATABASE_URL` | Neon pooled connection string | Application queries |
| `DATABASE_URL_UNPOOLED` | Neon direct connection string | Migrations only |
| `SECRET_KEY` | Long random secret | `python -c "import secrets; print(secrets.token_hex(32))"` |
| `APP_PASSWORD` | Your single-user password | Recommended for public deployments |
| `PUBLIC_BASE_URL` | `https://<your-service>.onrender.com` | Used in PWA metadata; update after the URL is known |
| `FLASK_APP` | `wsgi.py` | Set by `render.yaml` |

If deploying through `render.yaml`, variables marked `sync: false` must be entered in the Render dashboard before the first deploy. `SECRET_KEY` is generated by Render.

### Free-plan note

The Blueprint uses `plan: free`. Render's Free plan does not support `preDeployCommand`, so migrations and seeding run in the build command:

```yaml
buildCommand: pip install -r requirements.txt && FLASK_APP=wsgi.py flask db upgrade && FLASK_APP=wsgi.py flask seed-exercises
```

Do **not** put migrations in the Gunicorn start command: every instance would run them, which can race.

Free web services spin down after 15 minutes of inactivity and take about a minute to wake. That is fine for a personal logbook, but upgrade the compute plan if you need always-on availability. Data remains in Neon; only the local filesystem is ephemeral.

## 3. Build and start

`render.yaml` uses:

- Build: `pip install -r requirements.txt`, then `flask db upgrade` and `flask seed-exercises`
- Pre-deploy: none (unsupported on the Free plan)
- Start: `gunicorn wsgi:app --bind 0.0.0.0:$PORT --workers 2 --timeout 120 --access-logfile - --error-logfile -`
- Health check: `/api/health`

The health route stays available when `APP_PASSWORD` is enabled, so Render can verify the service without credentials.

Application logs reuse Gunicorn's error logger when available, and otherwise fall back to `INFO` logging on stdout.

## 4. First-deploy checklist

1. Push the repository to GitHub.
2. Create/reuse the Neon development branch and copy its pooled/direct URLs into Render.
3. Set a unique `SECRET_KEY` and an `APP_PASSWORD`.
4. Deploy the Blueprint or create the service with the commands above.
5. Confirm `/api/health` returns `{"ok": true, "service": "iron-oath"}`.
6. Sign in with `APP_PASSWORD`, then check that the dashboard loads.
7. Confirm the exercise library has 20 seeded movements.
8. Create a short program, log a workout, complete it, then verify Statistics and Personal Records.
9. Confirm that editing/deleting a plan or exercise leaves the completed workout intact.
10. Install the PWA on Android and desktop; verify the manifest and icons load.
11. Go offline, edit a set, come back online, and verify the pending-sync indicator clears without duplicate workouts.

## 5. HTTPS and PWA

Render provides HTTPS automatically. Add a custom domain in Render if desired; the service worker and install prompt require a secure origin (HTTPS or localhost).

The service worker is served at `/sw.js` with `Cache-Control: no-cache`, scope `/`, and caches:

- `/` and `/offline`
- manifest and icons
- CSS/JS and the local Chart.js bundle

Dynamic API responses are not cached. Offline workout edits are queued in IndexedDB and synced through `/api/sync/workouts`.

## 6. Verifying a migration safely

Before applying a new migration to the production Neon branch:

```bash
# Create a temporary branch from production, pull its direct URL, then:
$env:FLASK_APP = "wsgi.py"
flask db upgrade
python -c "from wsgi import app; c=app.test_client(); print(c.get('/api/health').status_code)"
python -m pytest
```

Only after the branch test passes should you run the same migration against `main`.

## 7. Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `relation "users" does not exist` | Migrations did not run | Check pre-deploy/build logs and `DATABASE_URL_UNPOOLED` |
| `prepared statement ... already exists` | Migration used pooled URL | Use the direct URL in `migrations/env.py` |
| Health check fails with 401 | `api.health` exempt missing | Confirm current `gymlog/__init__.py` is deployed |
| PWA install button never appears | HTTP origin or unsupported browser | Use HTTPS and a browser with install support |
| Offline edits remain pending | Sync endpoint rejected payload | Check browser console and Render logs; conflict is shown in the sync pill |
| Duplicate workouts after offline sync | `client_uuid` missing or changed | Ensure the workout page sends the stored `client_uuid` |
| PRs look wrong | PRs were not rebuilt | Complete/save the workout again; `recalculate_prs()` runs on completion and sync |
| Barbell Bench Press counts bodyweight on an older DB | Seed data from before the correction | Set `is_bodyweight = false` for that exercise, or re-seed a fresh branch |
